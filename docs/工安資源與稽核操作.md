# 工安資源與稽核操作

## 監控摘要

已核准會員可取得 GET `/api/v1/monitoring`；未登入或停用回傳 401。資料包含警示、稽核、啟用實驗室與攝影機資源。待辦數來自 SQLite，安全率為示範；資源數不是實際 CAM 連線數。主機鏡頭由 `/video` 手動開啟，不由新增資源自動啟動。

## 管理實驗室與攝影機

後台 `/admin` 的實驗室區輸入名稱與位置後新增；按修改可變更，按停用保留歷史事件。攝影機需歸屬有效且啟用實驗室，設備索引為非負整數。停用實驗室後，其攝影機不出現在一般會員清單，事件紀錄不刪除。

API：管理 `/api/v1/admin/laboratories`、`/api/v1/admin/cameras` 提供 GET／POST，`/{id}` 使用 PATCH 修改欄位與 active（0／1）。一般會員可讀取 GET `/api/v1/laboratories`、`/api/v1/cameras` 的啟用資源。資料變更須附 `X-CSRF-Token`；一般會員不得管理。

## 警示處理

後台警示區按「標示已處理」，更新後待辦數減少。初始化警示為示範，尚無自動辨識。

PATCH `/api/v1/admin/alerts/{id}`，JSON `{"status":"resolved"}`，成功 200；非法狀態 400、未知事件 404、重複處理 409。狀態及 handler_id 寫入 SQLite，重啟保留。

## 稽核建立與改善追蹤

管理者在 `/admin` 的「稽核紀錄」填寫區域、稽核人員、問題／改善事項及改善期限，即可建立狀態為 `open` 的待改善紀錄。日期欄位使用 `YYYY-MM-DD`；伺服器會再驗證日期是否存在。一般會員可透過監控摘要讀取稽核紀錄，但新增與更新操作限管理者。

- `POST /api/v1/admin/audits` 建立紀錄，JSON 欄位為 `area`、`inspector`、`issue`、`due_date`；有效時回傳 201 及新紀錄。
- `PATCH /api/v1/admin/audits/{id}` 搭配 `{"status":"completed"}` 標記改善完成，成功回傳 200。
- 欄位或日期無效回傳 400、未知紀錄回傳 404、重複完成回傳 409、未具管理權限回傳 403；Cookie 認證的請求須附 `X-CSRF-Token`。

儀表板的待改善數只統計 `open` 紀錄；建立或完成後重新載入清單與統計。稽核狀態持久化於 SQLite，重啟後仍保留。自動化操作與持久化驗證見 `tests/test_safety.py`；實際手機與桌面畫面仍由整體瀏覽器驗收確認。

## 資料保留

升級與初始化經版本 migration，僅新資料庫建立示範資料，清空後重啟不會補回。操作與持久化驗證見 `tests/test_safety.py`；升級資料保留見 `tests/test_migrations.py`。瀏覽器／離線體驗另列整體驗收。
