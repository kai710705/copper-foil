# 會員與管理操作

## 註冊、登入與密碼

註冊頁 `/register` 可選一般使用者或管理者；全部新帳號均為待審核。Email 需合法、密碼 8 至 128 字元，帳號不得重複。待審核、拒絕及停用帳號不可登入。

預設管理者為 `admin`／`admin@123`。首次登入導向 `/password`，請輸入目前與新密碼；新密碼不可沿用預設值，變更後才能使用管理功能。系統不會重設已修改密碼。

登出使用 POST；API／表單所有資料變更均要求 CSRF Token。登入後 Token 會重新產生，前端需使用最新值。被停用帳號的舊 Session 在下一個受保護請求立即失效。

## API 範例

1. `GET /api/v1/auth/csrf`，保存 Session Cookie，取得 `data.csrf_token`。
2. `POST /api/v1/auth/register`，JSON 為 `{"username":"student","email":"student@example.com","password":"a-valid-password","role":"user"}`；標頭附 `X-CSRF-Token`。成功 201；欄位／角色錯誤 400、重複 409。
3. `POST /api/v1/auth/login`，JSON 為帳號與密碼。成功 200 回傳 `data.user`、新的 `data.csrf_token` 與 `data.redirect`；未核准／密碼錯誤 401。
4. `POST /api/v1/auth/password`，JSON 為 `current_password`、`password`，使用登入後 Token；成功 200。未修改預設密碼操作管理 API 回傳 403／`PASSWORD_CHANGE_REQUIRED`。
5. `POST /api/v1/auth/logout`，附最新 Token；成功 200 並清除 Session。

錯誤格式固定為 `{"error":{"code":"...","message":"繁體中文訊息","details":null}}`；成功使用 `data`。沒有有效 Token 回傳 403／`CSRF`。會員輸出不含密碼雜湊。

驗證依據：`tests/test_members.py` 的註冊、登入改密碼與授權測試，及 `tests/test_video.py` 的 CAM 回歸測試。

## 會員審核後台

進入 `/admin`，選擇待審核篩選，按核准或拒絕，確認對話後更新會員。已核准會員可停用；不可停用自己或最後管理者。按「審核歷程」查看操作者、前後狀態與 UTC 時間。API 為 GET `/api/v1/admin/users?status=pending`、PATCH `/api/v1/admin/users/{id}` 與 GET `/api/v1/admin/users/{id}/history`。

核准後會員可登入；停用後其既有 Session 下一次請求立即拒絕。此端到端身分流程已以 API 測試，後台瀏覽器互動另列整合驗收任務。
