# 會員審核規格差異

## Purpose

讓已核准管理者審視會員申請並核准、拒絕或停用帳號，以保存完整狀態變更與操作者紀錄，使一般使用者及管理者的權限授予具有可追溯的依據。

## ADDED Requirements

### Requirement: 會員審核與停用
系統 SHALL 提供會員清單及待審核篩選；管理者可核准或拒絕待審核會員、停用已核准會員。未知會員回傳 404，無效狀態轉移回傳 409。系統 SHALL 防止管理者停用自己或停用最後一位已核准管理者。

#### Scenario: 核准待審核會員
- **WHEN** 管理者對待審核會員提交有效核准請求
- **THEN** 會員轉為 `approved`，之後可登入

#### Scenario: 一般會員嘗試審核
- **WHEN** 一般會員呼叫會員審核 API
- **THEN** 系統回傳 403，會員狀態不變

#### Scenario: 防止鎖死管理權限
- **WHEN** 管理者嘗試停用自己或最後一位已核准管理者
- **THEN** 系統回傳 409，管理帳號保持可用

### Requirement: 審核歷程
每次成功審核 SHALL 在同一交易保存會員 ID、操作者 ID、前後狀態與 UTC 更新時間，管理者可查詢歷程；一般使用者不可查看會員審核歷程。

#### Scenario: 審核結果可追溯
- **WHEN** 管理者核准會員後查詢該會員歷程
- **THEN** 顯示操作者、待審核到核准的變化及時間
